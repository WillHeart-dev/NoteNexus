# NoteNexus 技术文档

> 面向学生的学习小组知识共享与 AI 复习平台。本文档描述系统架构、模块划分、数据模型、核心流程与关键配置。
> 最后更新：2026-11-07

---

## 1. 定位与边界

**一组一群，群即边界。** 同学按课程/科目创建学习小组，资料、问答、练习、评论全部挂在小组下；任何跨组访问在 Service 层被拒绝，不依赖前端隐藏。

**两条主线，AI 只做两件事：**

1. **问答**——基于组内资料回答，必须给出处，证据不足时拒答；
2. **讲义**——把全组资料压缩成一份结构统一的复习稿。

除此之外的（练习、知识库评论、用户管理）都是围绕这两条主线的配套功能，不引入新的检索能力。

## 2. 系统架构

```
                    ┌──────────────────────────┐
                    │  Vue 3 + Vite (5173)     │
                    │  Pinia / Router / EP     │
                    └────────────┬─────────────┘
                                 │ HTTP + JWT
                    ┌────────────▼─────────────┐
                    │  Spring Boot 3 (10001)   │
                    │  Controller → Service    │
                    │  守卫统一鉴权 · 统一响应    │
                    └──┬────┬────┬────┬────────┘
                       │    │    │    │
        ┌──────────────┘    │    │    └───────────────┐
        ▼                   ▼    ▼                    ▼
  ┌──────────┐      ┌──────────┐ ┌──────────┐  ┌───────────┐
  │ MySQL 8  │      │ PG16 +   │ │ ES 8 +   │  │  MinIO    │
  │ 业务库    │      │ pgvector │ │ IK 分词   │  │ 对象存储   │
  │ 19 表    │      │ 向量检索  │ │ 关键词    │  │ 原件/讲义  │
  └──────────┘      └──────────┘ └──────────┘  └───────────┘
                                 │
                          ┌──────▼──────┐
                          │ DashScope   │
                          │ qwen-plus   │
                          │ embedding-v3│
                          └─────────────┘
```

**为什么是四套存储而不是一套：**

| 存储 | 职责 | 不放进 MySQL 的原因 |
|---|---|---|
| MySQL 8 | 用户、小组、资料元数据、问答记录、讲义、练习、评论 | — |
| PostgreSQL + pgvector | 切片向量（`vector(512)`，HNSW，余弦距离） | MySQL 无成熟向量索引；HNSW 的召回/延迟比在 MySQL 里做近似检索可控 |
| Elasticsearch 8 + IK | 切片全文倒排（`ik_max_word`） | 中文分词与 BM25 是 ES 的强项，MySQL 全文索引对中文支持差 |
| MinIO | 原始文件、生成的 Markdown 讲义 | 大文件不进数据库，走对象存储才有分片上传与预签名 |

一次检索同时打到 pgvector 与 ES，两路结果用 **RRF（Reciprocal Rank Fusion）** 融合——向量通道擅长语义近似，关键词通道擅长专有名词与编号，融合后优于任一路。

## 3. 模块划分

后端根包 `com.notenexus.rag`：

| 包 | 职责 | 关键类 |
|---|---|---|
| `auth` | 登录注册、JWT 签发与校验、刷新令牌、密码哈希 | `AuthService`、`JwtAccessTokenService`、`JwtAuthenticationFilter`、`RefreshTokenService` |
| `user` | 账号信息、改密、系统管理员的用户管理 | `AccountService`、`AdminUserService`、`UserQueryService` |
| `group` | 小组 CRUD、成员关系、邀请、加入申请 | `GroupManagementService`、`GroupMembershipService`、`GroupJoinRequestService` |
| `document` | 资料列表、分片上传（初始化/分片/完成）、预览、下载、删除 | `DocumentUploadService`、`DocumentQueryService`、`DocumentDownloadService` |
| `ingestion` | 解析 → 清洗 → 切片 → 向量化 → 落库的异步 ETL | `EtlDocumentIngestionProcessor`、`StructureAwareChunkTransformer`、`VectorIngestionService` |
| `engine` | 三类外部存储的适配层 | `PgVectorRetrievalAdapter`、`ElasticsearchChunkIndexService`、`MinioStorageService` |
| `qa` | 查询规划、混合检索、答案生成、引用装配、反馈 | `QaService`、`HybridChunkRetrievalService`、`QueryPlanningService`、`CitationAssembler` |
| `review` | 复习讲义生成（map/reduce + Markdown 组装 + 异步状态机） | `ReviewGenerationService`、`ReviewContentSynthesizer`、`MarkdownReviewDocumentBuilder` |
| `exercise` | 从资料抽题、作答判分、正确率统计 | `ExerciseExtractionService`、`ExerciseService` |
| `graph` | 知识点/关系抽取、图谱构建任务、学习路径规划 | `GraphExtractionService`、`KnowledgeGraphBuildService`、`LearningPathService`、`MasteryService` |
| `discussion` | 知识库评论（前端入口挂在学习资料模块底部，按群组即知识库维度存储） | `GroupDiscussionService` |
| `metrics` | LLM 调用记账（模块/端点/耗时/token/成本） | `LlmUsageCollector`、`LlmCostCalculator` |
| `common` | 统一响应、异常、枚举、日志切面、慢 SQL、双数据源、安全上下文 | `ApiResponse`、`GlobalExceptionHandler`、`LogAop`、`SlowSqlInterceptor`、`DataSourceConfiguration` |

分层约定：Controller 只做参数校验与响应封装；业务规则与权限判断在 Service；Mapper 只做数据访问，复杂 SQL（`FOR UPDATE` 行锁、联表过滤）放 `resources/mappers/*.xml`。

## 4. 权限模型

**两级正交**，互不推导：

| 层级 | 取值 | 作用范围 |
|---|---|---|
| 系统角色 `system_role` | `ADMIN` / `USER` | 用户管理、ETL 运维统计 |
| 组内角色 `group_role` | `OWNER` / `MEMBER` | 小组管理（改名、邀请审批、成员移除、删除资料） |

三条落地规则：

1. **不进业务区**：`requireBusinessUser()` 把 `ADMIN` 挡在小组/资料/问答之外——管理员没有业务数据的天然访问权，避免"运维账号能看所有学生资料"。
2. **读权限统一入口**：`requireGroupReadable(groupId)` 校验当前用户是该组成员（OWNER 或 MEMBER），所有资料/问答/练习/讲义接口都走它。
3. **写权限单独收口**：`requireGroupOwner(groupId)` 只给群主，用于小组管理与跨成员操作。

资源伪造（不存在的 ID、他人的文档 ID）统一返回"不存在或已删除"，不泄漏资源是否存在。

## 5. 数据模型

业务库 22 张表，按域分组：

| 域 | 表 |
|---|---|
| 账号 | `users`、`user_refresh_tokens` |
| 小组 | `notenexus_groups`、`group_memberships`、`group_invitations`、`group_join_requests` |
| 资料 | `documents`、`document_upload_sessions`、`document_upload_chunks`、`document_chunks`、`ingestion_jobs` |
| 问答 | `qa_records`、`qa_record_citations`、`qa_feedback` |
| 讲义 | `review_documents` |
| 练习 | `exercise_questions`、`exercise_attempts` |
| 评论 | `group_discussion_messages` |
| 图谱 | `knowledge_graph_nodes`、`knowledge_graph_edges`、`knowledge_graph_build_tasks` |
| 记账 | `llm_usage_records` |

设计要点：

- **`notenexus_groups`** 不叫 `groups`——`GROUPS` 是 MySQL 8.0 保留字，直接用会在 DDL 与部分 SQL 上报语法错。
- **资料状态机**：`UPLOADED → PROCESSING → READY / FAILED`。只有 `READY` 的资料参与检索与讲义生成。
- **切片双写**：`document_chunks` 存原文与元数据（MySQL），向量进 PG，倒排进 ES，三者用 `chunk_id` 对齐；重建索引时以 MySQL 为准。
- **引用快照**：`qa_record_citations` 保存回答当时命中的切片摘要与分数，资料被删后历史问答仍可追溯。
- **逻辑删除**：资料、讲义均走 `deleted` 标记，物理清理由后台异步执行。
- **向量表**：`vector_store`（PG），字段 `embedding vector(512)`，HNSW 余弦索引。

## 6. 核心流程

### 6.1 资料上传与 ETL

```
前端切片 → POST /documents/upload/init（返回 uploadId、已上传分片）
        → POST /documents/upload/chunks（并发分片，MD5 校验）
        → POST /documents/upload/complete（合并 → MinIO → 落 documents 记录）
        → 发布 DocumentIngestionRequestedEvent（事务提交后触发）
后台线程：
   CAS 抢占（PROCESSING）→ 下载对象 → 解析（txt/md/pdf/docx）
   → 文本清洗 → 结构感知切片（目标 240 / 最大 320 / 重叠 32 token）
   → Embedding（text-embedding-v3，512 维）→ 写 PG 向量 + 写 ES 索引
   → documents.status = READY（失败则 FAILED + failure_reason）
```

可靠性设计：

- **CAS 抢占**：`UPDATE ... SET status='PROCESSING' WHERE id=? AND status='UPLOADED'`，影响行数为 0 就放弃，避免重复事件导致重复处理。
- **秒传**：同组内文件 MD5 命中已有记录时直接建引用，不重复上传。
- **僵尸回收**：定时扫描长时间停留在 `PROCESSING` 的任务并置为 `FAILED`，服务重启不会留下永久卡死的资料。
- **解析器工厂**：`DocumentParserFactory` 按扩展名分发，新增格式只需实现 `DocumentParser`。

### 6.2 混合检索问答

```
问题 → 查询规划（LLM 判断是否需要拆分子问题 / 改写）
     → 并行检索：pgvector Top-K 10 ｜ ES Top-K 10
     → RRF 融合排序 → 取前 6 条作为证据（分数阈值 0.30）
     → 拼装上下文（带【来源：文件名】标注）→ LLM 生成
     → 解析答案 + 装配引用 + 四级证据评估
     → 持久化 qa_records / qa_record_citations
```

- **拒答优先于编造**：证据为空或全部低于阈值时直接返回"资料中未找到"，不调用生成。
- **四级证据等级**（`EvidenceLevel`）：直接支撑 / 部分支撑 / 间接相关 / 无支撑，随回答一起返回，让用户知道这句话有多硬。
- **引用可回溯**：每个引用带文件名、切片序号、相关度分数，点开可看原文片段。

### 6.3 复习讲义生成

```
POST /review-documents {groupId}
  → 校验：组内 READY 资料非空 → 落 review_documents（PENDING）→ 异步事件
后台：
  ① 取数：全组 READY 资料的切片，按文档分组
  ② map：逐篇提炼（要点 / 定义 / 公式 / 易错点），保留【来源：文件名】
  ③ reduce：六章合并
  ④ 组装：MarkdownReviewDocumentBuilder 拼封面信息 + 六章正文
  ⑤ 落盘：MinIO  review/{groupId}/{id}-{yyyyMMdd}.md（text/markdown）
  ⑥ 回写：COMPLETED + 文件名/大小/对象键/Markdown 源
```

固定六章：**复习导览 / 知识点精讲 / 易混对比 / 典型例题 / 自测题 / 考前速记卡**。

三个刻意的取舍：

1. **不让 LLM 直接排版**。模型只产出受控 Markdown（标题、列表、表格、公式），文档结构由 Java 侧拼装。直接让模型写 LaTeX/HTML 时，转义错误会让整份产物报废。
2. **全程溯源**。map 阶段就要求每条要点标来源，reduce 阶段禁止引入原文没有的内容。
3. **异步 + 轮询**。生成要多次调用 LLM（分钟级），接口立即返回 `PENDING`，前端 3 秒轮询状态；期间可以关页面，回来再下载。

状态机：`PENDING → GENERATING → COMPLETED / FAILED`，同样用 CAS 条件更新抢执行权，避免重复触发。

### 6.4 练习与知识库评论

- **练习**：`ExerciseExtractionService` 用 LLM 从指定资料的切片中抽选择题（题干/选项/答案/解析/出处），落 `exercise_questions`；作答写 `exercise_attempts`，统计按用户 + 小组聚合。
- **知识库评论**：纯 CRUD + 组内可见，无 AI 参与。评论按群组（知识库）维度存放，入口在学习资料模块底部，用于对整库的资料构成、组织方式发表整体评价，支持引用回复与撤回。

### 6.5 知识图谱与学习路径

**抽取与构建**（`graph` 模块，异步状态机与复习讲义一致）：

1. 发起构建：`KnowledgeGraphBuildService.createTask` 校验群组内有 `READY` 资料，落一条 `knowledge_graph_build_tasks`（`PENDING`）并发布事件；
2. 事务提交后 `@Async` 执行：逐份资料取前 30 个切片（上限 1 万字符），`GraphExtractionService` 用 LLM 抽取知识点与关系（提示词 `prompts/graph/extract.st`），要求每条关系附原文依据；
3. 归一合并：概念名归一化为 `node_key`（小写、去空白与标点），多份资料命中同一概念时合并释义、取更高重要度、累加来源；关系按「起点+终点+类型」去重并累加权重；
4. 原子落库：`KnowledgeGraphPersistenceService.replaceGraph` 在单事务内整体替换该群组的旧图（先删边再删点），避免中途失败留下半张图。

**学习路径**（`LearningPathService`）：

- 以 `PREREQUISITE_OF` 边为约束做 Kahn 拓扑分层，每轮取出前置全部满足的知识点作为同一阶段；`PART_OF` 反向视为弱前置（先整体后局部），避免只抽到层级结构时路径退化成单阶段；
- 检测到环时取剩余节点中入度最小者强行解锁并标记 `cycleDetected`，保证路径始终可生成；
- 阶段内按掌握度排序（薄弱 → 未检测 → 一般 → 已掌握），再按重要度降序；
- 无任何关系的孤立知识点归入末尾"独立知识点"阶段。

**掌握度**（`MasteryService`）：习题标签命中知识点名称（或题干包含）即视为关联题目，取用户最近一次作答计算正确率：≥ 0.85 `STRONG`、≥ 0.6 `MEDIUM`、< 0.6 `WEAK`、无题目或未作答 `UNTOUCHED`。图谱节点与路径条目都携带该档位，前端据此着色。

**前端**（`/app/graph`）：图谱视图为自研 SVG 力导向布局（斥力 + 弹簧 + 向心，确定性初值，无第三方依赖），支持滚轮缩放、拖拽平移、点选高亮邻接；学习路径为分阶段时间轴 + 优先补强清单。

## 11. 已知限制

| 限制 | 影响 | 后续 |
|---|---|---|
| 讲义生成无僵尸回收 | 服务在生成中重启，记录会停在 `GENERATING` | 参照 ETL 的 CAS + 定时回收补齐 |
